POST-MORTEM // ENGINEERING CHALLENGES

REAL PRODUCTION PROBLEMS
HOW THEY WERE SOLVED.

Engineering is defined by how bottlenecks and edge conditions are deconstructed. Here are three critical engineering challenges from actual production deployments.

CHALLENGE 01 • MEMORY OVERFLOW

High-Volume Excel Batch Ingestion & Memory Exhaustion

PROBLEM: Monthly SLA submissions from DISCOMs arrived as massive multi-sheet Excel workbooks causing ASP.NET memory spikes and GC pauses.

ROOT CAUSE: Default DOM-based spreadsheet parsers loaded entire files into RAM before validation.

APPROACH: Migrated to low-memory SAX stream parsing with batch staging in PostgreSQL.

SOLUTION: Streamed rows row-by-row into isolated staging tables, then executed bulk stored procedure validation inside a single transaction.

RESULT: 80% RAM Reduction • 0 Timeouts
CHALLENGE 02 • DISTRIBUTED AUTH

Cross-Server Session Desynchronization Across IIS Nodes

PROBLEM: Users transitioning between separate production server clusters under the UTel umbrella lost active login sessions.

ROOT CAUSE: Session state was tied to individual IIS worker memory with no shared session store across disparate networks.

APPROACH: Transitioned from stateful sessions to cryptographic, stateless token handshakes.

SOLUTION: Built a centralized auth gateway that signs cryptographic tokens validated across all nodes via public/private keys.

RESULT: Zero Session Dropouts • 100% Uptime
CHALLENGE 03 • RACE CONDITIONS

Concurrency & Race Conditions in Bulk SIM Recharges

PROBLEM: High-throughput bulk SIM recharge calls risked double-billing and ledger balance inconsistencies during surges.

ROOT CAUSE: Non-atomic read-modify-write cycles under high concurrent web requests.

APPROACH: Applied pessimistic row locks combined with unique client idempotency keys.

SOLUTION: Executed recharge operations inside SQL Server transactions using WITH (ROWLOCK, UPDLOCK) and pre-verified idempotency hashes.

RESULT: 100% Financial Accuracy • 0 Double Charges
